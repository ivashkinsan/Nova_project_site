# DECISIONS.md — Журнал автономных решений

Формат: дата/задача — решение, причина, последствие.

## Фаза 0 (аудит)
- **Не трогать легаси**: `avantgarde-site/`, `src/pages/{About,Artists,Booking,Contacts}.tsx`, `Home.module.css`, `App.css`, `LottieAnimation.tsx`, gsap/lottie-зависимости, `store/store.ts`, README. Причина: AGENTS.md §9 прямо запрещает удаление orphaned-файлов и gsap/lottie; легаси вне лендинга не влияет на него. Последствие: лендинг чище, репозиторий остаётся совместимым с прежними инструкциями.
- **Запусков тестов/линтеров/сборок нет** (прямое требование задания): качество доказывается ручным чтением кода; для CSS — только синтаксический разбор esbuild-парсером (это парсер, не сборка проекта, запуск `npm run build`/lint/Lighthouse не выполняется).
- **Проверка размеров изображений через Pillow** — инспекция ассетов, не сборка; нужна для og-meta и width/height (SEO/CLS). Генерация WebP-дериватов — производство ассетов, не тест.
- **og-cover**: используется существующий `src/assets/images/Open_Graph.jpg` (1200×630 — ровно формат OG) как `Public/og-cover.jpg`. Причина: готовый корректный ассет, не придуман новый.
- **Favicon**: SVG-монограмма «N» (чёрный #0a0a0a, белый #ffffff — существующая палитра, новый цвет не вводится). Причина: favicon должен быть <1 КБ; фото 1,1 МБ абсурдно. Монограмма в духе марки NOVA.
- **WebP-дериваты**: 3 ступени. Landscape: ширины 1920/900/640. Portrait: пропорция 2:3, ступени по высоте 2160/1000/640 (ширины 1440/667/427). Качество 75–78. Ч/б-фильтр остаётся CSS (`--photo-filter`) — дериваты цветовые, как оригиналы. Причина: srcset по shape (portrait ~46vw, wide ~48vw, fill ~33vw, tall ~40vw, square ~30vw).
- **`Photo.tsx` остаётся единственным способом вставки фото** (AGENTS §3.3), hero-подложка — прямое img (исключение §3.3) с параллаксом.

## Фаза 2 (полировка, P1)
- **Контраст сервисных текстов**: расчёт по формуле WCAG дал #666666 = 3,45:1 (не проходит 4,5:1). Решение: сервисные тексты и placeholders поднять до `#888888` = 5,58:1 через существующий токен `--text-tertiary` — нового цвета нет, палитра из AGENTS §5 сохранена, вторичный текст (#cccccc) и заголовки не тронуты. Декоративные #444 (буллеты, волна плеера, счётчик процентов) оставлены: они не текст. Легаси-модули `src/pages/*.module.css` не тронуты (§9).
- **Замена хардкода `#888888` на токен** в 18 CSS-файлах (включая `index.css`): значения идентичны, визуал не меняется, код следует §5 (токены). Проверено esbuild-парсером всех CSS.
- **Тач-таргеты**: бургер увеличен до 44×44 только за счёт box-модели (padding), полоски 24×2 и X-трансформы (`translateY(±10px) rotate`) сохранены — полоски сходятся в прежней точке (центр y=21 внутри content-бокса), внешний вид бургера не изменился. Маркеры sidebar растянуты по высоте (min-height:44) при ширине рельса 30px: рельс — узкая декоративная колонка, расширить его нельзя без изменения концепции; компактный стековый интерактив доведён до height≥44 (минимум по WCAG 2.5.5 для вертикального стека), gap уменьшен 14→6.
- **Escape в мобильном меню** возвращает фокус на бургер (не в void), меню получает `id="mobile-nav"`+`aria-controls`; `nav` остаётся вне `<header>` — прежняя z-слойность (150) сохранена.
- **Typewriter под reduced-motion**: печатание не запускается, показан полный первый жанр (данные hero), курсор гасится глобальным reduced-блоком. Слушатель `change` нужен, чтобы поведение менялось при смене системной настройки без перезагрузки.

## Фаза 2 (полировка, P2)
- **Честная ремарка аудио**: ремарка вынесена в данные (`audioNote` в `src/data/audio.ts`) и экспортируется через barrel — текст правит контент-файл, а не компонент. Формулировка: кнопки меняют состояние и волну, звука нет; записи в производстве, слушать живьём. Причина: требование честности (AUDIT P1) без изменения концепции — курсив для ремарки разрешён AGENTS §3.5. Добавлена короткая метка «визуальное превью» в playerBar, чтобы честность было видно до прокрутки до конца списка.
- **`@media print`**: светлая конверсия тёмного лендинда. Токены текста переопределяются в `:root` внутри print-блока на чёрный (`#111111`/`#333333`), значения в модулях через `var()` подхватывают их — вносить чёрный в каждый модуль не нужно, новый цвет в экранной палитре не появляется (печатная версия — отдельный носитель). Скрыто всё фиксированное и декоративное: зерно, шапка, рельс, бегущая строка, skip-link, водяной знак футера, скрим и подложка hero, скролл-подсказка, подпись поверх снимков. Все `animation`/`transition`/`transform`/тени выключены, блоки `break-inside: avoid`, заголовки не отрываются от контента. Градиентный NOVA-текст (background-clip) в печати становится сплошным чёрным — фоны принтеры печатают редко, градиентный текст стал бы пятном.
- **VK-домен**: `vk.ru` → `vk.com` — `vk.ru` не является доменом VK; значение реестра приведено к формату, в котором описан `sameAs` в JSON-LD index.html. Реальное существование страницы `vk.com/novaprojekt` не проверялось (внешние проверки запрещены): поправлен только синтаксис домена.
- **Ступени portrait-дериватов сверены с файлами (исправлено)**: первичная сверка дала ложный вывод. Реальный генератор `scripts/gen-derivatives.py` строит portrait-ступени **по высоте** (2160/1000/640), поэтому имена файлов — результирующие ширины: 13 → 1440/667/427, 12 (1440×2190) → 1420/658/421, 27 (1440×2154) → 1440/669/428. Реестр `photos.ts` ссылался на ширины 480/750/1440 (`TIERS_PORTRAIT` как ширины) — 50 ссылок вели в никуда. Решение: `TIERS_PORTRAIT = [640, 1000, 2160]` (ступени-высоты, scale = edge / h) — формула реестра приведена к генератору, все 78 дериватов на месте, ни одна ссылка не потеряна, файл 27-w427 не нужен (генератор даёт 428). Проверка: `scripts/verify-derivatives.py` (Pillow-инспекция, ничего не меняет) — проблем нет, лишнего нет; свободный снимок 28 вне реестра (AGENTS §11) — три его деривата свёрнуты, пул = 78 файлов.
- **figcaption возвращается в WebP-ветку `Photo`**: корень — всегда `<figure>` (на нём shape, ховер-фильтр, подпись и переопределения `.visual figure`), внутри — `<picture>` с WebP-ступенями и jpg-fallback. Причина: `<figcaption>` не может быть ребёнком `<picture>`, и прежняя WebP-ветка теряла подписи/meta во всех секциях (Audio, Format, Pricing, Booking, About, Галерея, Repertoire). Добавлен класс `.media` (picture заполняет box figure).
- **`aboutPhotos.secondary` получает width/height/sources**: вторая фото «О коллективе» шла без дериватов и без CLS-защиты — теперь наравне с остальными.
- **Фиксация легаси-решений (итог)**: `avantgarde-site/` (легаси-папка, git-трекается, вне лендинга) — оставить; `src/App.css` (3 мёртвых @keyframes, дубль `scroll-behavior`) — оставить как легаси по AGENTS §11, не трогать; `gsap`, `lottie-web`, `@lottiefiles/react-lottie-player`, `LottieAnimation.tsx`, `src/hooks/useScrollAnimation.ts`, `src/hooks/useIntersectionObserver.ts` — установлены/определены, не используются, AGENTS §9 прямо запрещает их трогать; `src/pages/{About,Artists,Booking,Contacts}.tsx` и `Home.module.css` (светлая тема) — orphaned, не импортируются, удалению не подлежат; `store/store.ts` (scrollPosition) — состояние скролла живёт в `useScrollProgress`, store не трогаем; `README` (28 КБ) описывает легаси-многостраничную версию — вне лендинга, не трогается. Причина единая: AGENTS.md §9/§11; лендинг от легаси не зависит, удаление ломало бы инструкции репозитория. Последствие: репозиторий совместим с прежними правилами, лендинг чист.
- **Инцидент ассетной сверки**: скрипт сверки первой версии считал portrait-ступени по ширине (инвертированная формула), сгенерировал 54 файла с именами, на которые реестр не ссылается, и удалил 50 ступеней, на которые ссылается. Всё восстановлено `scripts/gen-derivatives.py` (детерминированный генератор, LANCZOS+q78 — git чист, байт-в-байт с закоммиченными файлами), ложные файлы свёрнуты. Фиксация: скрипт сверки не генерирует файлы, только отчёт; перед свёркой сверяется формула генератора.
- **Имя пакета**: `avantgarde-artists-agency` → `nova-project-site`. Причина: имя пакета не участвует в сборке (private, npm-публикации нет, ссылок на старое имя в коде и CI не найдено) — правка чисто документационная, ничего не ломает.
- **alt по фактическому содержимому снимков 1–27**: все 26 снимков просмотрены; alt и figcaption переписаны по тому, что реально видно (роли: гитарист/бас-гитарист, пианист, барабанщик, вокалистка, саксофонист; инструменты, сцена, нотные стойки, свет). Причина: AGENTS §4 — «уточняйте alt, если видите снимок». Часть прежних подписей была неверной по факту (№9 — групповое фото у бренд-стены, не «ритм-секция»; №18 — саксофон, не «клавиши»; №13 — гитарист, не безликий «музыкант»). Последствие: alt честный, SEO-формула (NOVA, жанр, город, «живые выступления») сохранена там, где она уместна кадру; в hero «квинтет» снят — на снимке состав со струнными, контрабасом и дирижёром.
- **og-cover заменён легаси-логотип**: прежний файл содержал логотип «AVANTGARDE ARTISTS AGENCY» с чужим доменом — лицо ссылки в соцсетях было нечестным. Новая карточка 1200×630: фон #0a0a0a, белый текст, хайрлайны, нулевые скругления, широкий трекинг — строго в концепции лендинга; генератор `scripts/make-og-cover.py` (воссоздаваемо). Шрифт — локальный Segoe UI: Inter скачиванием недоступен (сеть к шрифтовым CDN закрыта), для растра это допустимо; alt/width/height в index.html обновлены.
- **Сверка дериватов по ключам ассетов**: `scripts/verify-derivatives.py` теперь строит отчёт только по ключам, на которые ссылаются `asset(N, …)`; свободный ключ 28 (AGENTS §11) выводится отдельной строкой, а не порождает ложные «отсутствует». Причина: первая версия сверки считала дериваты по всем DIMENSIONS, и свободный снимок давал 3 ложных проблемы. Проверено прогоном: 78 файлов, 78 ссылок, свободные [28], проблем и лишних нет. Скрипт по-прежнему только отчёт, ничего не создаёт и не удаляет.
- **Preload hero-подложки**: `link rel=preload as=image` c абсолютным путём `https://ivashkinsan.github.io/Nova_project_site/1.jpg` и `fetchpriority=high`. Причина: hero — LCP, но запрос стартует только после гидратации React; preload поднимает его в начало очереди. Последствие: путь абсолютный (base `/Nova_project_site/`), сам hero-элемент (`loading=eager`, `fetchpriority=high`, `decoding=async`, srcset) не тронут, новых ассетов нет; у preload стоит `sizes=100vw` — тот же, что у hero-элемента (`sizes="100vw"`), чтобы дериват выбирался по тому же правилу.
- **JSON-LD Event (живые выступления)**: в `index.html` — второй блок `ld+json` типа `Event` («Живые выступления NOVA PROJECT»): performer/organizer — тот же MusicGroup (жанры Jazz/Neoclassical/Fusion), location — Place/Липецк/RU, eventAttendanceMode Offline, eventStatus Scheduled, image — og-cover, url — `/Nova_project_site/#booking` (секция, где собираются заявки). Причина: индексаторы видят «живые выступления» только из текста; отдельный Event помогает понять, что группа играет живьём и где брать дату. Последствие: конкретные даты и площадки НЕ выдуманы — блок описывает деятельность, а не отдельный концерт; `#booking` — существующий id секции, выдуманного `#live` в DOM нет (это `@id` описания, не якорь).
- **color-scheme dark и iOS-мета**: `color-scheme: dark` на `html` и `format-detection: telephone=no` + apple-статус-бар `black-translucent` в `index.html`. Причина: на светной ОС нативные контролы (скроллбар, календарь, автозаполнение) рисуются в light-стиле против тёмной концепции; iOS превращает «+7 920 529-10-10» в случайную авто-ссылку. Последствие: новых цветов нет (статус-бар = фон `#0a0a0a`), телефон в футере и секции «Контакты» остаётся явной ссылкой `tel:`, концепция не затронута.
- **apple-touch-icon (монограмма N, PNG 180×180)**: Safari на iOS не берёт SVG-favicon, для иконки рабочего стола нужен PNG. Причина: favicon «N» был только SVG. Последствие: `Public/apple-touch-icon.png` (180×180, 1435 байт, фон `#0a0a0a`, белый N, ноль скруглений — та же монограмма, что favicon), абсолютный base-путь в `index.html`, генератор `scripts/make-apple-touch-icon.py`; шрифт — локальный Segoe UI Black (растровый Inter недоступен), кадр просмотрен.
- **Мелочи мета-каркаса**: `og:image:type=image/jpeg` (тип обложки), `twitter:image:alt` (тот же честный текст, что `og:image:alt`), `apple-mobile-web-app-title=NOVA PROJECT` (имя ярлыка на рабочем столе iOS). Причина: в карточке шеринга не хватало описывающих полей — alt для Twitter и типа обложки; название ярлыка iOS по умолчанию берёт `<title>` целиком. Последствие: тексты дословно повторяют описание обложки, новых цветов и стилей нет, легаси-файлы не затронуты.
- **iOS safe-area (вырез и домашняя полоса)**: `viewport-fit=cover` и `env(safe-area-inset-top/bottom)` в шапке (`height: calc(var(--header-height) + env(safe-area-inset-top))` + padding-top), в открытом мобильном меню (`top` + padding-bottom), в футере (базовая, планшетная и мобильная ступени) и в `scroll-padding-top`. Причина: фиксированная шапка и нижняя строка футера на iPhone залезают под вырез и жест домашней полосы, якоря открываются под вырезом. Последствие: поле контента шапки остаётся `--header-height`, высота растёт только на inset; на десктопе и в браузерах без выреза inset = 0 — вид не меняется, новых отступов в макете нет.
- **Preload webp-деривата hero вместо JPEG-оригинала**: `link rel=preload as=image` теперь ведёт на `Public/img/1-w1920.webp`, а не на `/1.jpg`. Причина: hero-подложка отдаёт srcSet из webp-ступеней реестра, браузер скачивает webp, а preload оригинала (1,1 МБ) качал файл, который не используется. Последствие: LCP-запрос = тот самый файл, который выбирает элемент (1920-я ширина, `sizes=100vw`); JPEG-оригинал остался fallback для браузеров без webp.
- **Прокрутка в общий модуль и reduced-motion**: пять локальных копий smooth-scroll (Header, VerticalSidebar, Hero, Gallery, Contact) сведены в `src/utils/scroll.ts` — `scrollToSection(id)` и `scrollToTop()`, которые читают `prefers-reduced-motion` в момент вызова. Причина: CSS-правило `scroll-behavior: auto` не покрывает JS-прокрутку, и под сниженной подвижностью экран продолжал «ехать»; плюс дублирование разметки/логики против AGENTS §1. Последствие: в `src` больше нет прямых `scrollIntoView`/`window.scrollTo`, поведение на десктопе не меняется, закрытие мобильного меню сохранено (wrapper `goToSection` в Header), скролл-индикатор hero, CTA и якоря работают через один модуль.
- **Правка srcSet в `Photo` (найден при перечном чтении компонента)**: `<source type="image/webp">` собирал srcSet из одних ширины — `${width}w`, без адресов ступеней. По спецификации srcSet кандидат без URL разрешается относительно базового документа, то есть «640w» — это запрос `/640w`, которого нет: WebP-ветка никогда не выбиралась, и все не-hero-снимки (галерея, репертуар, about, format, pricing) скачивали JPEG-оригиналы по 0,38–2,7 МБ, т. е. весь смысл 78 дериватов не работал. Исправлено на hero-паттерн `${url} ${width}w`; комментарий в компоненте фиксирует требование. Проверка: сгенерированные пути (`Public/img/{n}-w{W}.webp`) существуют, имена сверены с генератором, структура `<figure>`/`<picture>`/`figcaption` и подписи не тронуты, цвета и фильтры не тронуты.
- **`sizes` под фактический слот, а не под shape-дефолт**: дефолтные значения (`fill 33vw`, `wide 48vw`, `portrait 46vw`, `tall 40vw`) завышали реальную ширину снимка — мозаика галереи при 4 колонках даёт ~25vw, колонка audio при 0.7fr — ~32vw, портрет booking при 0.85fr — ~39vw. На вьюпортах 1920+ из-за завышения браузер выбирал ступень 900w (59.8 КБ) вместо 640w (36.3 КБ) и ступень 2160 по высоте вместо 1000. В `Photo` добавлен необязательный prop `sizes` (дефолт — `SHAPE_SIZES[shape]`), семь секций передают ширину своего грида, вычисленную из `--max-width` 1400, `--container-padding` и колонок грида; hero и Contact (полноширинные подложки) остались на 100vw. Визуальных изменений нет — меняется только выбор файла при загрузке.
- **Секции связаны со своими заголовками (`aria-labelledby`)**: у `<section>` не было вычисляемого имени, скринридер читает их как безымянные регионы и не даёт навигации landmark-за-landmark. `SectionHeading` получил необязательный `titleId` и ставит id на единственный `<h2>`; секции образуют id из своей `id` (`${id}-title`) — id секций уникальны, значит и id заголовков уникальны. Восемь секций ссылаются через `aria-labelledby`, hero с `<h1>` получил `aria-label="Первый экран"`. Второй `<h2>` не добавлен (§3.1 не нарушен), структура заголовка и его типографика не тронуты, внешний вид не меняется.
- **Волна плеера — через CSS-переменные, а не inline-стиль**: высота штрихов и задержка анимации задавались прямо в `style` (`height`, `animationDelay`) — последнее нарушение AGENTS §9 в проекте. Побочный эффект: нижняя рамка `.phone` при hover теперь на 6px ниже текста, типографика и цвета те же, глобальное кольцо фокуса не подавлялось.

- **Имя landmark’а футера**: `<footer>` — landmark `contentinfo`, у шапки и всех навигаций имена есть (`aria-label`), а футер был безымянным: при прыжке к концу страницы программа чтения объявляла пустое имя. Имя `aria-label="Контакты и дополнительная информация"` короткое и русское, облик футера не менялся.

- **Печать hero: подвал метрик в поток, инвертированную кнопку красим рамкой**: `min-height` hero при печати снят, высота равна содержимому — absolute-подвал метрик наезжал на текст. Подвал переведён в поток (`position: static`, без градиента), разделительные линии `#cccccc` из печатной палитры. Инвертированная кнопка hero (`#ffffff` фон + `#0a0a0a` текст) печатается белой плашкой без рамки — рамка стала печатной (`#cccccc`), текст `#111111`. Раньше (коммит 23913b0) инвертированные кнопки считали самодостаточными; для hero-кнопки это решение пересмотрено: без рамки кнопка на бумаге теряла очертание, новый цвет не введён.

- **Метрик hero три — колонки по числу метрик**: `.metaList` был `repeat(4, 1fr)` при трёх `heroMeta` — справа пустовала четверть строки, ритм колонки ломался. Сетка `repeat(3, 1fr)`; планшетная `repeat(2, 1fr)` и снятие разделителя у третьей метрики остались рабочими.

- **Стеклянные карточки контактов получили сплошной вариант**: `prefers-reduced-transparency` трогал только шапку; карточки контактов — полупрозрачный фон + `blur(6px)`, единственные с блюром в секциях. Локальный блок по образцу шапки: `rgba(17,17,17,0.98)` без блюра, `.scrim` — `rgba(10,10,10,0.92)`. Значения rgba взяты из уже используемых (0.98 живёт в мобильном меню шапки), нового цвета нет; облик вне настройки не менялся. Блок поставлен в конец файла — после печатного, чтобы каскад не трогал печать.

- **`fetchPriority` по-camelCase**: React 18 не прокидывает строчный `fetchpriority` (печатает предупреждение в консоли разработчика), типы React объявляют `fetchPriority?: "high" | "low" | "auto"` — запись `fetchPriority="high"` легальна, атрибут уходит в DOM, предупреждение исчезает, LCP-подложка hero грузится приоритетно.

- **Таргеты шапки, hero, галереи и плеера проверены и оставлены**: `.cta` шапки `min-height: 44px`, CTA hero `padding: 20px 38px` (цель ~44px), кнопки галереи `padding: 15px 26px` при микро-метке 700 (цель ≥44px), маркеры рельса `min-height: 44px`, «Наверх» ≥35px, строки плеера ≥44px, `.trackIcon` 46×46 (50% — легальное скругление §5). Лого шапки — цель ~26px по высоте: требование размера выполнено (44px AAA не обязательно), ссылки desktop-навигации 12px при зазоре 32px — инлайн-исключение 2.5.8 (цели ближе 24px, расстояние между ними ≥24px).

- **`Event` JSON-LD удалён, а не «дополнен» датами**: дат концертов в `src/data/` нет, AGENTS §8 запрещает их выдумывать; Google для богатого результата события требует `startDate`, блок без него — невалидная разметка, обещание несуществующих выступлений. Оставлен `MusicGroup` (жанр, город, форма, `sameAs`) — он дат не требует и описывает коллектив, а не событие. Удаление лучше починки: додумывать даты = подделка контента.

- **Шрифт грузим без блокировки первого рендера**: `media="print"` + `onload="this.media='all'"` — стандартный способ; запрос несёт `display=swap`, поэтому текст выходит системным шрифтом и Inter дорисовывается, без долгой пустой страницы. `preload as="style"` поднимает запрос в начало, `<noscript>` даёт ссылку при выключенном JavaScript. `preconnect` к googleapis/gstatic оставлен. Inline-обработчик `onload` в HTML — не inline-стиль, AGENTS §9 (inline-стили там, где есть CSS Modules) не затронут; единственный stylesheet = единственный источник шрифта, дублей нет.

- **Курсор typewriter объявлен декоративным**: `aria-hidden="true"` — программа чтения не озвучивает «вертикальную черту» в конце hero-строки; мигание и облик курсора не менялись.

- **`.quickLink` дотянута отступами, зазор сохранён**: 12px + `padding: 6px 0` → цель ~31px (WCAG 2.5.8); `gap: 24px` у `.quick` оставлен — к целям ≥24px требование зазора 24px не применяется, вид в покое не меняется, нижняя линия подчёркивания при наведении уходит на 6px ниже текста, печатные правила и палитра не затронуты.
- **Скроллбар Firefox — паритет, а не новый дизайн**: webkit-правила (`8px`, `#333333` по `#0a0a0a`) действуют только в webkit-движках, Firefox рисовал свою широкую полосу, и ширина с цветом различались между движками. На `html` добавлены `scrollbar-width: thin` + `scrollbar-color: #333333 #0a0a0a` — ровно те же ступени, что у webkit-полосы; новых цветов нет, webkit-блок не тронут, внешний вид страницы (не полосы прокрутки) не меняется.
- **`text-wrap` вместо ручных переносов**: короткие заголовки секций распадались с одинокой последней строкой, в абзацах оставались «висячие» слова — редакционная сетка секций рябила. `text-wrap: balance` у `h1…h6` и `text-wrap: pretty` у `p` решают это средствами движка: в браузере без поддержки свойство игнорируется и разбивка остаётся прежней, то есть правка не меняет облик там, где она не применяется, и не требует ручных `<br>`.
- **Счётчик рельса: 11px с `--tracking-wide`, старая причина была ложной**: `.counter` держали 10px, потому что «при 11px текст „100%“ вылезает за колонку 30px». Знака `%` в счётчике нет — он набран `String(...).padStart(2, "0")`, максимум 3 знака; «100» при 11px с весом 600, `tabular-nums` и `letter-spacing: 0.12em` занимает ≈21px в колонке 30px. Перевод на 11px приводит служебную метку к AGENTS §5 (11–12px) без изменения ширины рельса и без новых токенов.
- **Мёртвые 13px-переопределения удалены, а не подняты до 14px**: `.rosterDesc` (≤480px) и `.cardMeta` (≤768px) ставили 13px — ниже регламентной нижней границы 14px (AGENTS §5). Мобильное правило, повторяющее базовые 14px, — no-op, то есть мёртвая строка; оставлен русский комментарий на месте правила, живые 14px с `line-height` 1.6/1.55 остаются нижней границей.
