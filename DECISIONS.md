# DECISIONS.md — Журнал автономных решений

Формат: дата/задача — решение, причина, последствие.

## Фаза 0 (аудит)
- **Не трогать легаси**: `avantgarde-site/`, `src/pages/{About,Artists,Booking,Contacts}.tsx`, `Home.module.css`, `App.css`, `LottieAnimation.tsx`, gsap/lottie-зависимости, `store/store.ts`, README. Причина: AGENTS.md §9 прямо запрещает удаление orphaned-файлов и gsap/lottie; легаси вне лендинга не влияет на него. Последствие: лендинг чище, репозиторий остаётся совместимым с прежними инструкциями.
- **Запусков тестов/линтеров/сборок нет** (прямое требование задания): качество доказывается ручным чтением кода; для CSS — только синтаксический разбор esbuild-парсером (это парсер, не сборка проекта, запуск `npm run build`/lint/Lighthouse не выполняется).
- **Проверка размеров изображений через Pillow** — инспекция ассетов, не сборка; нужна для og-meta и width/height (SEO/CLS). Генерация WebP-дериватов — производство ассетов, не тест.
- **og-cover**: используется существующий `src/assets/images/Open_Graph.jpg` (1200×630 — ровно формат OG) как `Public/og-cover.jpg`. Причина: готовый корректный ассет, не придуман новый.
- **Favicon**: SVG-монограмма «N» (чёрный #0a0a0a, белый #ffffff — существующая палитра, новый цвет не вводится). Причина: favicon должен быть <1 КБ; фото 1,1 МБ абсурдно. Монограмма в духе марки NOVA.
- **WebP-дериваты**: 3 ступени. Landscape: ширины 1920/900/640. Portrait: пропорция 2:3, ступени по высоте 2160/1000/640 (ширины 1440/667/427). Качество 75–78. Ч/б-фильтр остаётся CSS (`--photo-filter`) — дериваты цветовые, как оригиналы. Причина: srcset по shape (portrait ~46vw, wide ~48vw, fill ~33vw, tall ~40vw, square ~30vw).
- **`Photo.tsx` остаётся единственным способом вставки фото** (AGENTS §3.3), hero-подложка — прямое img (исключение §3.3) с параллаксом.

## Фаза 2 (полировка, P1)
- **Контраст сервисных текстов**: расчёт по формуле WCAG дал #666666 = 3,45:1 (не проходит 4,5:1). Решение: сервисные тексты и placeholders поднять до `#888888` = 5,58:1 через существующий токен `--text-tertiary` — нового цвета нет, палитра из AGENTS §5 сохранена, вторичный текст (#cccccc) и заголовки не тронуты. Декоративные #444 (буллеты, волна плеера, счётчик процентов) оставлены: они не текст. Легаси-модули `src/pages/*.module.css` не тронуты (§9).
- **Замена хардкода `#888888` на токен** в 18 CSS-файлах (включая `index.css`): значения идентичны, визуал не меняется, код следует §5 (токены). Проверено esbuild-парсером всех CSS.
- **Тач-таргеты**: бургер увеличен до 44×44 только за счёт box-модели (padding), полоски 24×2 и X-трансформы (`translateY(±10px) rotate`) сохранены — полоски сходятся в прежней точке (центр y=21 внутри content-бокса), внешний вид бургера не изменился. Маркеры sidebar растянуты по высоте (min-height:44) при ширине рельса 30px: рельс — узкая декоративная колонка, расширить его нельзя без изменения концепции; компактный стековый интерактив доведён до height≥44 (минимум по WCAG 2.5.5 для вертикального стека), gap уменьшен 14→6.
- **Escape в мобильном меню** возвращает фокус на бургер (не в void), меню получает `id="mobile-nav"`+`aria-controls`; `nav` остаётся вне `<header>` — прежняя z-слойность (150) сохранена.
- **Typewriter под reduced-motion**: печатание не запускается, показан полный первый жанр (данные hero), курсор гасится глобальным reduced-блоком. Слушатель `change` нужен, чтобы поведение менялось при смене системной настройки без перезагрузки.

## Фаза 2 (полировка, P2)
- **Честная ремарка аудио**: ремарка вынесена в данные (`audioNote` в `src/data/audio.ts`) и экспортируется через barrel — текст правит контент-файл, а не компонент. Формулировка: кнопки меняют состояние и волну, звука нет; записи в производстве, слушать живьём. Причина: требование честности (AUDIT P1) без изменения концепции — курсив для ремарки разрешён AGENTS §3.5. Добавлена короткая метка «визуальное превью» в playerBar, чтобы честность было видно до прокрутки до конца списка.
- **`@media print`**: светлая конверсия тёмного лендинда. Токены текста переопределяются в `:root` внутри print-блока на чёрный (`#111111`/`#333333`), значения в модулях через `var()` подхватывают их — вносить чёрный в каждый модуль не нужно, новый цвет в экранной палитре не появляется (печатная версия — отдельный носитель). Скрыто всё фиксированное и декоративное: зерно, шапка, рельс, бегущая строка, skip-link, водяной знак футера, скрим и подложка hero, скролл-подсказка, подпись поверх снимков. Все `animation`/`transition`/`transform`/тени выключены, блоки `break-inside: avoid`, заголовки не отрываются от контента. Градиентный NOVA-текст (background-clip) в печати становится сплошным чёрным — фоны принтеры печатают редко, градиентный текст стал бы пятном.
- **VK-домен**: `vk.ru` → `vk.com` — `vk.ru` не является доменом VK; значение реестра приведено к формату, в котором описан `sameAs` в JSON-LD index.html. Реальное существование страницы `vk.com/novaprojekt` не проверялось (внешние проверки запрещены): поправлен только синтаксис домена.
- **Ступени portrait-дериватов сверены с файлами (исправлено)**: первичная сверка дала ложный вывод. Реальный генератор `scripts/gen-derivatives.py` строит portrait-ступени **по высоте** (2160/1000/640), поэтому имена файлов — результирующие ширины: 13 → 1440/667/427, 12 (1440×2190) → 1420/658/421, 27 (1440×2154) → 1440/669/428. Реестр `photos.ts` ссылался на ширины 480/750/1440 (`TIERS_PORTRAIT` как ширины) — 50 ссылок вели в никуда. Решение: `TIERS_PORTRAIT = [640, 1000, 2160]` (ступени-высоты, scale = edge / h) — формула реестра приведена к генератору, все 78 дериватов на месте, ни одна ссылка не потеряна, файл 27-w427 не нужен (генератор даёт 428). Проверка: `scripts/verify-derivatives.py` (Pillow-инспекция, ничего не меняет) — проблем нет, лишнего нет; свободный снимок 28 вне реестра (AGENTS §11) — три его деривата свёрнуты, пул = 78 файлов.
- **figcaption возвращается в WebP-ветку `Photo`**: корень — всегда `<figure>` (на нём shape, ховер-фильтр, подпись и переопределения `.visual figure`), внутри — `<picture>` с WebP-ступенями и jpg-fallback. Причина: `<figcaption>` не может быть ребёнком `<picture>`, и прежняя WebP-ветка теряла подписи/meta во всех секциях (Audio, Format, Pricing, Booking, About, Галерея, Repertoire). Добавлен класс `.media` (picture заполняет box figure).
- **`aboutPhotos.secondary` получает width/height/sources**: вторая фото «О коллективе» шла без дериватов и без CLS-защиты — теперь наравне с остальными.
- **Фиксация легаси-решений (итог)**: `avantgarde-site/` (легаси-папка, git-трекается, вне лендинга) — оставить; `src/App.css` (3 мёртвых @keyframes, дубль `scroll-behavior`) — оставить как легаси по AGENTS §11, не трогать; `gsap`, `lottie-web`, `@lottiefiles/react-lottie-player`, `LottieAnimation.tsx`, `src/hooks/useScrollAnimation.ts`, `src/hooks/useIntersectionObserver.ts` — установлены/определены, не используются, AGENTS §9 прямо запрещает их трогать; `src/pages/{About,Artists,Booking,Contacts}.tsx` и `Home.module.css` (светлая тема) — orphaned, не импортируются, удалению не подлежат; `store/store.ts` (scrollPosition) — состояние скролла живёт в `useScrollProgress`, store не трогаем; `README` (28 КБ) описывает легаси-многостраничную версию — вне лендинга, не трогается. Причина единая: AGENTS.md §9/§11; лендинг от легаси не зависит, удаление ломало бы инструкции репозитория. Последствие: репозиторий совместим с прежними правилами, лендинг чист.
- **Инцидент ассетной сверки**: скрипт сверки первой версии считал portrait-ступени по ширине (инвертированная формула), сгенерировал 54 файла с именами, на которые реестр не ссылается, и удалил 50 ступеней, на которые ссылается. Всё восстановлено `scripts/gen-derivatives.py` (детерминированный генератор, LANCZOS+q78 — git чист, байт-в-байт с закоммиченными файлами), ложные файлы свёрнуты. Фиксация: скрипт сверки не генерирует файлы, только отчёт; перед свёркой сверяется формула генератора.
- **Имя пакета**: `avantgarde-artists-agency` → `nova-project-site`. Причина: имя пакета не участвует в сборке (private, npm-публикации нет, ссылок на старое имя в коде и CI не найдено) — правка чисто документационная, ничего не ломает.
- **alt по фактическому содержимому снимков 1–27**: все 26 снимков просмотрены; alt и figcaption переписаны по тому, что реально видно (роли: гитарист/бас-гитарист, пианист, барабанщик, вокалистка, саксофонист; инструменты, сцена, нотные стойки, свет). Причина: AGENTS §4 — «уточняйте alt, если видите снимок». Часть прежних подписей была неверной по факту (№9 — групповое фото у бренд-стены, не «ритм-секция»; №18 — саксофон, не «клавиши»; №13 — гитарист, не безликий «музыкант»). Последствие: alt честный, SEO-формула (NOVA, жанр, город, «живые выступления») сохранена там, где она уместна кадру; в hero «квинтет» снят — на снимке состав со струнными, контрабасом и дирижёром.
- **og-cover заменён легаси-логотип**: прежний файл содержал логотип «AVANTGARDE ARTISTS AGENCY» с чужим доменом — лицо ссылки в соцсетях было нечестным. Новая карточка 1200×630: фон #0a0a0a, белый текст, хайрлайны, нулевые скругления, широкий трекинг — строго в концепции лендинга; генератор `scripts/make-og-cover.py` (воссоздаваемо). Шрифт — локальный Segoe UI: Inter скачиванием недоступен (сеть к шрифтовым CDN закрыта), для растра это допустимо; alt/width/height в index.html обновлены.
- **Сверка дериватов по ключам ассетов**: `scripts/verify-derivatives.py` теперь строит отчёт только по ключам, на которые ссылаются `asset(N, …)`; свободный ключ 28 (AGENTS §11) выводится отдельной строкой, а не порождает ложные «отсутствует». Причина: первая версия сверки считала дериваты по всем DIMENSIONS, и свободный снимок давал 3 ложных проблемы. Проверено прогоном: 78 файлов, 78 ссылок, свободные [28], проблем и лишних нет. Скрипт по-прежнему только отчёт, ничего не создаёт и не удаляет.
- **Preload hero-подложки**: `link rel=preload as=image` c абсолютным путём `https://ivashkinsan.github.io/Nova_project_site/1.jpg` и `fetchpriority=high`. Причина: hero — LCP, но запрос стартует только после гидратации React; preload поднимает его в начало очереди. Последствие: путь абсолютный (base `/Nova_project_site/`), сам hero-элемент (`loading=eager`, `fetchpriority=high`, `decoding=async`, srcset) не тронут, новых ассетов нет; у preload стоит `sizes=100vw` — тот же, что у hero-элемента (`sizes="100vw"`), чтобы дериват выбирался по тому же правилу.
- **JSON-LD Event (живые выступления)**: в `index.html` — второй блок `ld+json` типа `Event` («Живые выступления NOVA PROJECT»): performer/organizer — тот же MusicGroup (жанры Jazz/Neoclassical/Fusion), location — Place/Липецк/RU, eventAttendanceMode Offline, eventStatus Scheduled, image — og-cover, url — `/Nova_project_site/#booking` (секция, где собираются заявки). Причина: индексаторы видят «живые выступления» только из текста; отдельный Event помогает понять, что группа играет живьём и где брать дату. Последствие: конкретные даты и площадки НЕ выдуманы — блок описывает деятельность, а не отдельный концерт; `#booking` — существующий id секции, выдуманного `#live` в DOM нет (это `@id` описания, не якорь).
- **color-scheme dark и iOS-мета**: `color-scheme: dark` на `html` и `format-detection: telephone=no` + apple-статус-бар `black-translucent` в `index.html`. Причина: на светной ОС нативные контролы (скроллбар, календарь, автозаполнение) рисуются в light-стиле против тёмной концепции; iOS превращает «+7 920 529-10-10» в случайную авто-ссылку. Последствие: новых цветов нет (статус-бар = фон `#0a0a0a`), телефон в футере и секции «Контакты» остаётся явной ссылкой `tel:`, концепция не затронута.
- **apple-touch-icon (монограмма N, PNG 180×180)**: Safari на iOS не берёт SVG-favicon, для иконки рабочего стола нужен PNG. Причина: favicon «N» был только SVG. Последствие: `Public/apple-touch-icon.png` (180×180, 1435 байт, фон `#0a0a0a`, белый N, ноль скруглений — та же монограмма, что favicon), абсолютный base-путь в `index.html`, генератор `scripts/make-apple-touch-icon.py`; шрифт — локальный Segoe UI Black (растровый Inter недоступен), кадр просмотрен.
- **Мелочи мета-каркаса**: `og:image:type=image/jpeg` (тип обложки), `twitter:image:alt` (тот же честный текст, что `og:image:alt`), `apple-mobile-web-app-title=NOVA PROJECT` (имя ярлыка на рабочем столе iOS). Причина: в карточке шеринга не хватало описывающих полей — alt для Twitter и типа обложки; название ярлыка iOS по умолчанию берёт `<title>` целиком. Последствие: тексты дословно повторяют описание обложки, новых цветов и стилей нет, легаси-файлы не затронуты.
- **iOS safe-area (вырез и домашняя полоса)**: `viewport-fit=cover` и `env(safe-area-inset-top/bottom)` в шапке (`height: calc(var(--header-height) + env(safe-area-inset-top))` + padding-top), в открытом мобильном меню (`top` + padding-bottom), в футере (базовая, планшетная и мобильная ступени) и в `scroll-padding-top`. Причина: фиксированная шапка и нижняя строка футера на iPhone залезают под вырез и жест домашней полосы, якоря открываются под вырезом. Последствие: поле контента шапки остаётся `--header-height`, высота растёт только на inset; на десктопе и в браузерах без выреза inset = 0 — вид не меняется, новых отступов в макете нет.
- **Preload webp-деривата hero вместо JPEG-оригинала**: `link rel=preload as=image` теперь ведёт на `Public/img/1-w1920.webp`, а не на `/1.jpg`. Причина: hero-подложка отдаёт srcSet из webp-ступеней реестра, браузер скачивает webp, а preload оригинала (1,1 МБ) качал файл, который не используется. Последствие: LCP-запрос = тот самый файл, который выбирает элемент (1920-я ширина, `sizes=100vw`); JPEG-оригинал остался fallback для браузеров без webp.
- **Прокрутка в общий модуль и reduced-motion**: пять локальных копий smooth-scroll (Header, VerticalSidebar, Hero, Gallery, Contact) сведены в `src/utils/scroll.ts` — `scrollToSection(id)` и `scrollToTop()`, которые читают `prefers-reduced-motion` в момент вызова. Причина: CSS-правило `scroll-behavior: auto` не покрывает JS-прокрутку, и под сниженной подвижностью экран продолжал «ехать»; плюс дублирование разметки/логики против AGENTS §1. Последствие: в `src` больше нет прямых `scrollIntoView`/`window.scrollTo`, поведение на десктопе не меняется, закрытие мобильного меню сохранено (wrapper `goToSection` в Header), скролл-индикатор hero, CTA и якоря работают через один модуль.
- **Правка srcSet в `Photo` (найден при перечном чтении компонента)**: `<source type="image/webp">` собирал srcSet из одних ширины — `${width}w`, без адресов ступеней. По спецификации srcSet кандидат без URL разрешается относительно базового документа, то есть «640w» — это запрос `/640w`, которого нет: WebP-ветка никогда не выбиралась, и все не-hero-снимки (галерея, репертуар, about, format, pricing) скачивали JPEG-оригиналы по 0,38–2,7 МБ, т. е. весь смысл 78 дериватов не работал. Исправлено на hero-паттерн `${url} ${width}w`; комментарий в компоненте фиксирует требование. Проверка: сгенерированные пути (`Public/img/{n}-w{W}.webp`) существуют, имена сверены с генератором, структура `<figure>`/`<picture>`/`figcaption` и подписи не тронуты, цвета и фильтры не тронуты.
- **`sizes` под фактический слот, а не под shape-дефолт**: дефолтные значения (`fill 33vw`, `wide 48vw`, `portrait 46vw`, `tall 40vw`) завышали реальную ширину снимка — мозаика галереи при 4 колонках даёт ~25vw, колонка audio при 0.7fr — ~32vw, портрет booking при 0.85fr — ~39vw. На вьюпортах 1920+ из-за завышения браузер выбирал ступень 900w (59.8 КБ) вместо 640w (36.3 КБ) и ступень 2160 по высоте вместо 1000. В `Photo` добавлен необязательный prop `sizes` (дефолт — `SHAPE_SIZES[shape]`), семь секций передают ширину своего грида, вычисленную из `--max-width` 1400, `--container-padding` и колонок грида; hero и Contact (полноширинные подложки) остались на 100vw. Визуальных изменений нет — меняется только выбор файла при загрузке.
- **Секции связаны со своими заголовками (`aria-labelledby`)**: у `<section>` не было вычисляемого имени, скринридер читает их как безымянные регионы и не даёт навигации landmark-за-landmark. `SectionHeading` получил необязательный `titleId` и ставит id на единственный `<h2>`; секции образуют id из своей `id` (`${id}-title`) — id секций уникальны, значит и id заголовков уникальны. Восемь секций ссылаются через `aria-labelledby`, hero с `<h1>` получил `aria-label="Первый экран"`. Второй `<h2>` не добавлен (§3.1 не нарушен), структура заголовка и его типографика не тронуты, внешний вид не меняется.
- **Волна плеера — через CSS-переменные, а не inline-стиль**: высота штрихов и задержка анимации задавались прямо в `style` (`height`, `animationDelay`) — последнее нарушение AGENTS §9 в проекте. Имя `aria-label="Контакты и дополнительная информация"` короткое и русское, облик футера не менялся.

- **Печать hero: подвал метрик в поток, инвертированную кнопку красим рамкой**: `min-height` hero при печати снят, высота равна содержимому — absolute-подвал метрик наезжал на текст. Подвал переведён в поток (`position: static`, без градиента), разделительные линии `#cccccc` из печатной палитры. Инвертированная кнопка hero (`#ffffff` фон + `#0a0a0a` текст) печатается белой плашкой без рамки — рамка стала печатной (`#cccccc`), текст `#111111`. Раньше (коммит 23913b0) инвертированные кнопки считали самодостаточными; для hero-кнопки это решение пересмотрено: без рамки кнопка на бумаге теряла очертание, новый цвет не введён.

- **Метрик hero три — колонки по числу метрик**: `.metaList` был `repeat(4, 1fr)` при трёх `heroMeta` — справа пустовала четверть строки, ритм колонки ломался. Сетка `repeat(3, 1fr)`; планшетная `repeat(2, 1fr)` и снятие разделителя у третьей метрики остались рабочими.

- **Стеклянные карточки контактов получили сплошной вариант**: `prefers-reduced-transparency` трогал только шапку; карточки контактов — полупрозрачный фон + `blur(6px)`, единственные с блюром в секциях. Локальный блок по образцу шапки: `rgba(17,17,17,0.98)` без блюра, `.scrim` — `rgba(10,10,10,0.92)`. Значения rgba взяты из уже используемых (0.98 живёт в мобильном меню шапки), нового цвета нет; облик вне настройки не менялся. Блок поставлен в конец файла — после печатного, чтобы каскад не трогал печать.

- **`fetchPriority` по-camelCase**: React 18 не прокидывает строчный `fetchpriority` (печатает предупреждение в консоли разработчика), типы React объявляют `fetchPriority?: "high" | "low" | "auto"` — запись `fetchPriority="high"` легальна, атрибут уходит в DOM, предупреждение исчезает, LCP-подложка hero грузится приоритетно.

- **Таргеты шапки, hero, галереи и плеера проверены и оставлены**: `.cta` шапки `min-height: 44px`, CTA hero `padding: 20px 38px` (цель ~44px), кнопки галереи `padding: 15px 26px` при микро-метке 700 (цель ≥44px), маркеры рельса `min-height: 44px`, «Наверх» ≥35px, строки плеера ≥44px, `.trackIcon` 46×46 (50% — легальное скругление §5). Лого шапки — цель ~26px по высоте: требование размера выполнено (44px AAA не обязательно), ссылки desktop-навигации 12px при зазоре 32px — инлайн-исключение 2.5.8 (цели ближе 24px, расстояние между ними ≥24px).

- **`Event` JSON-LD удалён, а не «дополнен» датами**: дат концертов в `src/data/` нет, AGENTS §8 запрещает их выдумывать; Google для богатого результата события требует `startDate`, блок без него — невалидная разметка, обещание несуществующих выступлений. Оставлен `MusicGroup` (жанр, город, форма, `sameAs`) — он дат не требует и описывает коллектив, а не событие. Удаление лучше починки: додумывать даты = подделка контента.

- **Шрифт грузим без блокировки первого рендера**: `media="print"` + `onload="this.media='all'"` — стандартный способ; запрос несёт `display=swap`, поэтому текст выходит системным шрифтом и Inter дорисовывается, без долгой пустой страницы. `preload as="style"` поднимает запрос в начало, `<noscript>` даёт ссылку при выключенном JavaScript. `preconnect` к googleapis/gstatic оставлен. Inline-обработчик `onload` в HTML — не inline-стиль, AGENTS §9 (inline-стили там, где есть CSS Modules) не затронут; единственный stylesheet = единственный источник шрифта, дублей нет.

- **Курсор typewriter объявлен декоративным**: `aria-hidden="true"` — программа чтения не озвучивает «вертикальную черту» в конце hero-строки; мигание и облик курсора не менялись.

- **`.quickLink` дотянута отступами, зазор сохранён**: 12px + `padding: 6px 0` → цель ~31px (WCAG 2.5.8); `gap: 24px` у `.quick` оставлен — к целям ≥24px требование зазора 24px не применяется, вид в покое не меняется, нижняя линия подчёркивания при наведении уходит на 6px ниже текста, печатные правила и палитра не затронуты.
- **Скроллбар Firefox — паритет, а не новый дизайн**: webkit-правила (`8px`, `#333333` по `#0a0a0a`) действуют только в webkit-движках, Firefox рисовал свою широкую полосу, и ширина с цветом различались между движками. На `html` добавлены `scrollbar-width: thin` + `scrollbar-color: #333333 #0a0a0a` — ровно те же ступени, что у webkit-полосы; новых цветов нет, webkit-блок не тронут, внешний вид страницы (не полосы прокрутки) не меняется.
- **`text-wrap` вместо ручных переносов**: короткие заголовки секций распадались с одинокой последней строкой, в абзацах оставались «висячие» слова — редакционная сетка секций рябила. `text-wrap: balance` у `h1…h6` и `text-wrap: pretty` у `p` решают это средствами движка: в браузере без поддержки свойство игнорируется и разбивка остаётся прежней, то есть правка не меняет облик там, где она не применяется, и не требует ручных `<br>`.
- **Счётчик рельса: 11px с `--tracking-wide`, старая причина была ложной**: `.counter` держали 10px, потому что «при 11px текст „100%“ вылезает за колонку 30px». Знака `%` в счётчике нет — он набран `String(...).padStart(2, "0")`, максимум 3 знака; «100» при 11px с весом 600, `tabular-nums` и `letter-spacing: 0.12em` занимает ≈21px в колонке 30px. Перевод на 11px приводит служебную метку к AGENTS §5 (11–12px) без изменения ширины рельса и без новых токенов.
- **Мёртвые 13px-переопределения удалены, а не подняты до 14px**: `.rosterDesc` (≤480px) и `.cardMeta` (≤768px) ставили 13px — ниже регламентной нижней границы 14px (AGENTS §5). Мобильное правило, повторяющее базовые 14px, — no-op, то есть мёртвая строка; оставлен русский комментарий на месте правила, живые 14px с `line-height` 1.6/1.55 остаются нижней границей.
- **Числовые claims README проверены и переписывать не потребовалось**: перемеренные по исходникам медиа-метрики (`@media` 72, print 16, reduced-motion 5, forced-colors 1, `:focus-visible` 9, `aria-*` 62, `lang="en"` 16, safe-area 8, theme-color 1, robots 1, preload 2, og 11, twitter 5) не встречались в README числовыми строками, и ложных строк про `prefers-reduced-motion`/`prefers-color-scheme` meta нет: таких meta не существует. Факты зафиксированы в AUDIT/REPORT, а README дополнен строками про Firefox-скроллбар, `text-wrap`, регламентные ступени и счётчик 11px.

- **Граница play-кнопки: `#333333` → `--text-muted` (`#666666`)**: круг кнопок play/pause — граница UI-компонента, WCAG 1.4.11 требует ≥3:1; `#333333` по `#0a0a0a` даёт 1.60:1, из палитры порог берут `#666666` (3.45:1) и выше, поэтому выбор падает на светшую из приемлемых ступеней — минимально заметный сдвиг в существующей шкале, без нового цвета. `border-radius: 50%` сохранён: легаси-принятая ступень правила «нуль скруглений». `flex-shrink: 0` снят — элемент лежит в грид-строке и свойства не использует, то есть мёртвая строка.
- **`.playerState` оставлен на `--tracking-wide`, остальные метки плеера — на `--tracking-eyebrow`**: AGENTS §5 требует служебную метку 11–12px + 0.22em. Расширение меток пересчитано по знакам в самом узком слоте (колонка плеера ≈572px при 1025–1200px): «05 ФРАГМЕНТА» ≈102px, «ВИЗУАЛЬНОЕ ПРЕВЬЮ» ≈161px, «NOVA PROJECT» ≈108px, «4:23» ≈37px, «01» ≈19px — все вписываются, и они переведены на 0.22em. `.playerState` — строка 12px `nowrap` «Сейчас: Midnight Swing», она занимает ту же полосу с латинским названием; расширение на ~10% угрожало горизонтальному обрезу именно в 1025–1200px (AGENTS §5: этот диапазон — точечный breakpoint плеера), поэтому оставлен прежний трекинг. Метрика важнее формального единообразия: обрезанная строка ломает облик, а разный трекинг двух меток в одной полосе — нет.
- **17px при 1025–1200px оставлен числом**: токена под 17px в `variables.css` нет (шкала: 16 `--font-size-body`, 18 `--font-size-text`), а вводить новый токен = расширять шкалу; правило в узком диапазоне оставлено прежним, базовый `.trackTitle` (18px) и мобильный (16px) переведены на токены.
- **Мёртвые правила удалены, а не «починены»**: `.trackActive .playArrow` (стрелка рендерится только когда трек не активен — `AudioSection.tsx` L83–90), `.trackActive .waveBar` (дубль `.waveBarActive`) и печатные no-op `.trackActive .trackTitle`/`.trackActive .trackDuration` правили ничего не меняли; на их месте русские комментарии. `.trackActive .trackIndex` в печатном блоке сохранён — он поднимает индекс с `#333333` до `#111111`, то есть работает. `.player` убран из печатной группы (фон и цвет у него задаются в блоке выше).
- **Название активного трека в `aria-live` — `lang="en"`**: регион собирается в русской фразе `Сейчас: Midnight Swing`; без `lang="en"` программа чтения читала латиницу русскими правилами (WCAG 3.1.2). Облик, порядок announce и счётчик (`padStart(2, "0")`) не меняются, русской остаётся и служебная фраза режима («визуальное превью»).
- **Ползунок скроллбара — UI-компонент: цвет пересчитан по WCAG 1.4.11, ширина не тронута**: полоса прокрутки — элемент интерфейса, её ползунок обязан читаться на фоне дороги (≥3:1). `#333333` по `#0a0a0a` — 1.60:1, из палитры порог берут `#666666` (3.45:1) и выше, поэтому webkit-ползунок на `var(--text-muted)`, состояние под курсором — на `var(--text-tertiary)` (`#888888`, 5.56:1), дорога — `var(--bg)` (тот же фон страницы). Firefox-пара на `html` переведена на ровно те же токены: паритет движков держится на совпадении значений, и менять его в одну сторону нельзя.
- **Ширину скроллбара (8px / `thin`) не увеличиваем**: минимальный размер цели 2.5.8 (24px) применяется к целям, которыми управляет сам сайт; цель, которую обслуживает пользовательский агент — полоса прокрутки браузера — из исключения. Утолщение полосы до 24px перекроило бы принятую редакционную тонкую полосу, то есть визуальную концепцию, а задача требует только усиливать и полировать в её рамках: правка коснулась цвета, ширина и скругление (`border-radius: 0`) не менялись.
- **`sizes` фото «Звук» — 90vw при ≤1024px**: колонка секции при 1024px ≈944px, снимок занимает её почти целиком; прежняя планка переоценивала слот, и браузер выбирал ступень с запасом. `(max-width: 1024px) 90vw, 32vw` подбирает файл под реальную ширину; `srcSet` реестра (`640w`/`900w`/`1440w`) при 90vw даёт ≈850px — берётся ступень 900w, а не лишние 1440w.
- **19px → `var(--font-size-text)` (18px), а не новый токен**: акцентный первый абзац секции «О коллективе» стоял на 19px — вне регламентной body-полосы 14–18px (AGENTS §5), и шкала `variables.css` размера 19px не содержит. Вводить токен 19px значило бы расширять типографическую шкалу; акцентность первого абзаца держится размерной парой 18/17 и ступенью цвета (`--text-secondary` против `--text-tertiary`), поэтому правка возвращает модуль в шкалу без изменения облика: `line-height: 1.7`, цвет, отступы и ремарка не тронуты, 17px внутри полосы оставлен числом (токена 17px нет).
- **Печатные цвета текста убраны как накрываемые, а не «починены»**: `.paragraph` и `.rosterDesc` в печатной группе модуля красили var-driven текст в `#333333`, а глобальный печатный блок `index.css` переназначает `--text-*` в `:root` — эти строки были избыточны. Настоящий дефект лежал в специфичности: `.paragraph:first-child` (0,2,0) с литерным `#cccccc` печатная группа с селектором `.paragraph` (0,1,0) не накрывала, и на белой бумаге акцентный абзац давал 1.61:1. После перевода всех цветов текста на токены ручные печатные цвета модулю не нужны; `#111111` оставлен только там, где он поднимает узел над служебной ступенью (`.rosterIndex`).
- **Границы потомков секции глобальная печать не красит — рельсы состава задаём локально**: глобальный печатный блок задаёт `border-color: #cccccc` для `section`, `main`, `footer` и `footer *`, но не для потомков секции, поэтому полупрозрачные белые рельсы списка состава (на бумаге невидимые) перекрашиваются в модуле: `.roster` и `.rosterItem` на `#cccccc`. `background-color: transparent` из печатной группы убран: фон строки состава появляется только под курсором, курсора в печати нет, то есть строка была no-op.
- **Инвертированные цели (белая подложка + тёмный текст) оставляем числами, а не переводим на токены**: печатный remap красит `--text-primary` в `#111111`, а `--bg` не переназначается — белая кнопка заявки на токене печаталась бы тёмной плашкой с тёмным текстом (1.13:1). Белая подложка печатается светом бумаги, текст на ней остаётся читаемым; комментарий в модуле объясняет, почему числа там остаются. Отдельно замечу: hover-ступень `#e0e0e0` переведена на существующий токен `--color-grey-lighter`, нового цвета нет.
- **Отметка выбранного формата — символ, а не инвертированная цель: её переводим на токен**: белый кружок на белой бумаге невидим; на `var(--text-primary)` печатный remap делает его тёмным диском, экранный облик (белый диск на тёмном фоне) не меняется.
- **`transition: all` на карточке радиовыбора сужен до `border-color 0.3s ease`**: `all` переводил бы все свойства карточки, включая шрифт, отступы и положение; ховер у карточки меняет ровно границу, и регламентная ховер-физика (AGENTS §3.5, `--transition-normal` по времени) сохранена.
- **Длинная метка «ЭЛЕКТРОННАЯ ПОЧТА» влезает в мобильную колонку с `--tracking-eyebrow`**: при 12px и 0.22em строка из 17 знаков занимает ~171px, мобильная колонка формы с отступом 22px шире — перевод лейблов на регламентный трекинг (AGENTS §5) не ломает раскладку. Служебные индексы шагов (`01`…`08`) остаются на `--tracking-wide: 0.12em`: AGENTS §3.5 требует широкого трекинга чисел через `--tracking-*`, не обязательно eyebrow.
- **data-URI стрелки `select` не знает CSS-переменных**: ступень `#888888` (`--text-tertiary`) продублирована числом; это единственный литерный hex модуля, он закомментирован, новый цвет не введён.
- **Печатные цвета текста секции заявки убраны как накрываемые, хайрлайны потомков задаём локально**: глобальный печатный блок перекрашивает `section`, `main`, `footer` и `footer *`, но не содержимое секции — полупрозрачные белые хайрлайны колонок, шагов, строк сводки и значка итога на бумаге невидимы, поэтому они заданы ступенью `#cccccc` внутри модуля. Ручные печатные цвета текста, фон и цвет секции убраны: их накрывает глобальный remap `--text-*` и правило для `section`.
- **Тач-таргет ссылок навигации растянут поляром, а не видимым блоком**: регламент WCAG 2.5.8 требует поля ≥24×24, а текст ссылки и подчёркивание обязаны остаться на прежних местах. Поэтому поле `.desktopNavLink` выросло за счёт `padding: 6px 0` и `min-height: 24px`, а подчёркивание, висевшее на `bottom: -6px`, прижато к нижнему краю поля (`bottom: 0`) — после роста поля линия стоит на том же расстоянии от текста, то есть облик пиксель в пиксель. Расстояние между соседними ссылками поднято до 24px только в уплотнённой навигации (≤1100px), где они стоят рядом как inline-ссылки; у целей ≥24px (кнопки шапки 44px, маркеры рельса 30×44px) требование расстояния не применяется, поэтому их разрывы (6px между маркерами) не тронуты.
- **Инвертированные цели шапки переводим на токены: печать их не касается**: правило цикла #52 (оставлять белую подложку числами) действует там, где белая плашка печатается. Шапка и `#mobile-nav` скрыты в печати глобальным `display: none !important`, поэтому белой плашки на бумаге нет, и перевод `.cta:hover`/`.navCta` на `var(--text-primary)` + `var(--bg)` не создаёт дефект 1.13:1 — комментарий в модуле это фиксирует.
- **Трекинг ссылок мобильного меню сведён к `--tracking-wide`**: он держал произвольный `0.08em`, а AGENTS §3.5 требует широкого трекинга через `--tracking-*`; десктопные ссылки навигации уже на `--tracking-wide`, и мобильные приведены к той же шкале, чтобы навигация говорила одним голосом. Проверка вписывания: labels ≤12 знаков при 16px в 335px колонке — 0.12em добавляет ~0.64px на знак, запас есть.
- **Счётчик рельса — палитровая ступень через токен, а не число**: `#444444` заменён существующим токеном `--color-placeholder`; метка служебная, `aria-hidden` и скрыта в печати, поэтому контраст к ней не предъявляется, но цвет обязан быть из палитры через токен.
- **Сплошная подложка мобильного меню при `prefers-reduced-transparency`**: блюр убирался, а полупрозрачная подложка `rgba(10,10,10,0.95)` без блюра даёт «грязный» фон под текстом; взято значение, которое уже использует открытое меню (`0.98`) — нового цвета нет, экранные значения не менялись.
- **Своих блоков фокуса, `prefers-reduced-motion` и печати в этих модулях не добавляли**: кольцо фокуса даёт глобальное `:focus-visible` из `index.css` (переведено на `var(--text-primary)`, печатается тушью через remap), hover-переходы обнуляет глобальный reduced-motion блок, печать шапки не описывается (она скрыта глобально), рельс уже скрыт в печати локальным `display: none`.
- **Инвертированные ховер-состояния переводим на токены, а базовые инвертированные цели — нет**: правило цикла #52 (белую подложку оставить числами) действует там, где плашка печатается. Печатаются только базовые правила: ховер-состояние кнопки «Наверх» в печати не участвует, поэтому его перевод на `var(--text-primary)`/`var(--bg)` не создаёт дефект 1.13:1, а базовая граница кнопки на `var(--border-hover)` печатается чернильной линией (`#333333`, 12.4:1). Комментарий в модуле это фиксирует.
- **Водяной знак и маркер списка футера — палитровые ступени через существующие токены**: `#1a1a1a` → `var(--card-bg-hover)`, `#444444` → `var(--color-placeholder)`; оба декоративны (`aria-hidden`, знак скрыт в печати), нового цвета нет, цвета обязаны быть из палитры через токен, а не числом.
- **Печатный блок футера сокращаем, но фон снимаем локально**: глобальное правило `footer *` перекрашивает фон, текст и границы всех потомков футера, глобальный remap `--text-*` красит служебные ступени — ручные группы текста и границ избыточны. Чёрная плашка футера на токене `--bg` специфичностью класса (0,1,0) выше глобального `footer` (0,0,1), поэтому снятие фона обязано остаться локальным; поднятие ссылок и лого-«PROJECT» до заголовочной ступени `#111111` — печатная иерархия, а не дубль.
- **Ссылкам разделов футера дали регламентную межстрочность**: они стоят в полосе body 14–18px (AGENTS §5) без `line-height`, у них был только `font-size: 15px`; `line-height: 1.6` визуальных однострочных лейблов не меняет и поднимает зону нажатия.
- **Латинский водяной знак получил `lang="en"` (WCAG 3.1.2)**: даже `aria-hidden`-текст читается языком рендеринга, и в проекте латиница уже размечена (`NOVA`, `PROJECT`, `VK`, имя группы, копирайт) — всего 5 разметок в футере.
- **Разрывы ссылок футера не поднимали до 24px**: все цели футера ≥24px (лого ~42px, телефон ~34px, соцссылка ~30px, ссылки разделов ~31px, кнопка «Наверх» ~36px, skip-link ~32px), по WCAG 2.5.8 требование расстояния к ним не применяется, поэтому `gap: 12`/`gap: 14` между строками остались как часть редакционной раскладки.
- **Карточки связи сделали списком (`ul`/`li`)**: три канала связи — повторяющийся блок, и для программы чтения это список из трёх пунктов, а не набор `<div>`. Семантику списка возвращает `role="list"`/`role="listitem"`, потому что `list-style: none` в WebKit её снимает; UA-отступ и маркер списка сброшены в модуле, сетка 3 → 2 → 1 и правило `.card:last-child` сохранены, облик не менялся.
- **Печатный блок секции контактов сокращён до плашек и хайрлайнов**: цвет текста карточек перекрашивает глобальный remap `--text-*` (все классы текста на токенах), поэтому ручные `#333333` и `#111111` убраны; глобальные `section` и `footer *` не достают до содержимого секции, поэтому снятие чёрного фона секции, фон и граница карточки и подчёркивание значения остались локальными — фон секции на токене `--bg` (remap его не красит) снимается именно классом, чья специфичность выше `section`.
- **Непрозрачные стопы градиента затемнения переведены на `var(--bg)`**: значения `#0a0a0a` совпадают с токеном, печати блок не касается (подложка и затемнение скрыты в печати), полупрозрачные `rgba(10, 10, 10, …)` оставлены числами — полупрозрачных токенов в шкале нет, нового цвета нет.
- **Тач-таргеты контактов не растягивали**: ссылки значения и кнопка стоят на ступени 26px с `line-height: 1.2`, их поле ~31px (≥24×24), по WCAG 2.5.8 требование расстояния 24px к ним не применяется, поэтому `gap: 24`/`gap: 14` между карточками остались частью редакционной раскладки.
- **Печатные блоки формата и стоимости сокращены до двух правил каждый**: цвет текста перекрашивает глобальный remap `--text-*` (весь текст секций на токенах), поэтому ручные `#333333` и `#111111` убраны; группы `.block` и `.notes` убраны, потому что на экране у них нет ни фона, ни границы — печатное `background-color`/`border-color` для них ничего не меняло. Локально остались снятие чёрного фона секции (фон на токене `--bg`, remap его не красит, специфичность класса выше `section`) и печатные хайрлайны списков: глобальные `section` и `footer *` не достают до содержимого секции.
- **Ховер-правила переведены на токены без печатного риска**: плашка строки «что включено» и белый индекс под курсором печатаются только при наведении, а печать наведение игнорирует — их перевод на `var(--card-bg)` и `var(--text-primary)` (значения совпадают с литерами) безопасен; базовая левая граница ремарок на `var(--border-hover)` печатается тушью (12.40:1 на бумаге), поэтому отдельное печатное правило ей не нужно.
- **Межстрочность служебных строк списков поднята до 1.6**: `.blockItem` (15px) и `.itemText` (16px) держали `line-height: 1.55` — ниже нижней границы регламентной полосы body 14–18px (AGENTS §5); высота строк выросла на ~1px, раскладка блоков и сетка «что включено» не изменились, остальные ступени секций уже были внутри полосы.
- **Семантика списка возвращена через `role`**: списки «детали формата» и «что включено» стоят на `list-style: none`, который в WebKit снимает роль списка; `role="list"` на `<ul>` и `role="listitem"` на `<li>` возвращают её без изменения сетки, границ строк и ховер-плашки.
- **Интерактивных целей в этих секциях нет, поэтому WCAG 2.5.8 не применяли**: строки «что включено» и «детали формата» реагируют на наведение как декор (плашка + сдвиг), кликабельных ссылок и кнопок в секциях нет; локальный `prefers-reduced-motion` не добавляли — hover-переходы обнуляет глобальный блок, локальный был бы дублем.
- **Инвертированную кнопку «Обсудить вечер» и полосу подсветки карточек репертуара оставили литералами**: белая плашка/граница/тёмный текст кнопки и белая 1px-полоса по верхней грани — из той же печатной ловушки: перевод на `var(--text-primary)` красит их печатным remap в `#111111`, и инвертированная кнопка печаталась бы тёмной плашкой с почти чёрным текстом (контраст ~1.13:1), а полоса репертуара печаталась бы тушью на всех карточках (в печати `transform` снимается, полоса полной ширины). Литералы в печати невидимы/печатается текст кнопки; ховер-ступень `#e0e0e0` совпадает с токеном и наведена — в печати не участвует, её перевели.
- **Печатные блоки галереи и репертуара сокращены до трёх правил каждый**: цвет текста перекрашивает глобальный remap `--text-*` (весь текст секций на токенах), поэтому ручные `#333333`/`#111111` убраны; в репертуаре убрана и группа `border-color` для карточек и ячеек фото — границ на экране у них нет, печатное правило ничего не меняло. Локально остались снятие фонов (специфичность класса выше глобального `section`), перестройка сетки снимков и печатные хайрлайны примечания, мозаики и кнопок.
- **Семантику мозаик не меняли**: галерея — сетка подписанных снимков `<figure>`, репертуар — смесь карточек `<article>` и ячеек фото с фото; это не список, `list-style: none` там не используется, поэтому `role="list"`/`role="listitem"` не требуется — в отличие от списков формата, стоимости и контактов.
- **Разрыв 14px между кнопками галереи не поднимали**: обе кнопки стоят на ступени 11px с полями `15px 26px` — поле ~43px по высоте, по WCAG 2.5.8 к целям ≥24×24 требование расстояния 24px не применяется, поэтому `gap: 14` сохранён как часть подвала секции; карточки репертуара и ячейки фото не кликабельны, интерактивных целей там нет.
- **Лид первого экрана оставили с `line-height: 1.3`**: это дисплейная ступень (на десктопе clamp 18–28px, на мобильном 16–22px), а не body-текст, к которому §5 требует 1.6–1.8; межстрочность 1.3 задана и в базовом `h1`, её «выравнивание» подняло бы лид героя и изменило ритм первого экрана. Ремарка секции «Звук» (14px) и название трека (18px) уже стоят в полосе (1.7 и 1.6), поэтому body-полосу применяли только к текстовым ступеням.
- **Инвертированную кнопку «Оставить заявку» оставили белыми литералами**: белая плашка, белая рамка и тёмный текст того же печатного плана, что и кнопка галереи — перевод на токены красил бы плашку печатным remap в `#111111` с почти чёрным текстом (контраст ~1.13:1), то есть печать ломалась; печатное правило снимает фон и задаёт цвет `#111111`, поэтому экранный литерал остаётся. Ховер-ступень `#e0e0e0` переведена на `var(--color-grey-lighter)` — значение токена совпадает, а наведение в печать не попадает.
- **Печатные цвета текста героя и секции «Звук» убрали как дубли remap**: весь их текст на токенах `--text-*`, а глобальный печатный блок переназначает токены в `:root` (→ `#111111`/`#333333`), поэтому ручные группы `#333333`/`#111111` (цвет секции, сервисные ступени, лид, надзаголовок, значения метрик, название трека) ничего не меняли. Остались правила, где есть фон, рамка или перекрас: снятие фонов, печатные хайрлайны подвала метрик, колонок метрик, строк треков, полосы плеера и ремарки, рамки обеих кнопок героя, сплошной NOVA и цвет инвертированной кнопки.
- **Границы содержимого секции задаём локально**: глобальный печатный блок перекрашивает границы `section`, `main`, `footer` и потомков футера, но не потомков секции, поэтому хайрлайны подвала метрик, полос плеера и ремарки (полупрозрачный белый, в печати невидимый) переведены в печать ступенью `#cccccc` внутри модуля.
- **Роль списка вернули списку треков и подвалу метрик первого экрана**: оба стоят на `list-style: none`, который в WebKit снимает семантику списка; `role="list"` и `role="listitem"` возвращают её без изменения грида, полей строк и сетки метрик, `aria-hidden` на декоративных частях не тронут.
- **`lang="en"` подвалу метрик не добавляли**: значения `heroMeta` — цифры (`5`, `2`, `60`) и русские подписи, цифры нейтральны к языку; англоязычные названия треков и авторов в секции «Звук» уже размечены `lang="en"` (включая название активного трека), заголовки NOVA/PROJECT — тоже.
- **Локальный блок `prefers-reduced-motion` героя оставили**: он называет анимации дрейфа подложки и стрелки «листайте» (§5 требует явного упоминания там, где есть анимация), глобальный блок обнуляет переходы и прячет зерно — локальный не дублирует их, а JS-страховка параллакса (`matchMedia`) остаётся обязательной, потому что параллакс пишется в CSS-переменную из `requestAnimationFrame`.
- **Роли списков возвращены всем спискам с `list-style: none` в общих компонентах**: навигация (мобильная и десктопная), колонка «Разделы» и примечания футера, маркеры рельса, состав коллектива, пять шагов заявки. WebKit снимает семантику списка при `list-style: none`, программа чтения перестаёт объявлять количество элементов; `role="list"`/`role="listitem"` возвращают её, не трогая грид, поля и разрывы. `<dl>` сводки заявки — не список, роль ему не нужна.
- **Базовую межстрочность 1.6 задали на `body`**: текст вне `<p>` (испан, подписи, ячейки) наследовал браузерный normal ≈1.2, то есть был ниже нижней границы body-полосы §5. Заголовки (1.1) и `<p>` (1.6) переопределяют её своими правилами, плотные дисплейные ступени (phone-номер 1.5, значения метрик) задают свою. Индекс шага `.stepIndex` зафиксирован на 1.2 — служба 11px вне полосы, и базовая 1.6 подняла бы строку, съев компенсацию `padding-top: 3px`.
- **Межстрочность 1.6 добавили точечно пяти правилам**: `.navLink`, `.phone`, `.rosterName`, `.radioLabel`, `.textarea` — все это 15–18px-текст без межстрочности, то есть нарушение body-полосы §5; высота строк выросла на 1–4px, сетки и поля не менялись. `.input` и `.select` — однострочные поля, межстрочность им не нужна; `.trackTitle` стоит на `white-space: nowrap` с обрезкой, полоса к нему не применяется.
- **Литерные размеры с отсутствующей ступенью оставили числами**: 13/15/17/20/22/26px и трекинги 0.1em/0.14em в шкале `variables.css` не представлены; перевод на соседнюю ступень менял бы размер лого, кликабельного номера телефона и навигации, то есть облик. Перевели только совпадающие значения (16/18/14px), облик не изменился.
- **`autoComplete` и `querySelector<HTMLElement>` — правки типов, не поведения**: React принимает только camelCase-проп `autoComplete` (строчный `autocomplete` не проходит типизацию), в HTML он уходит строчным атрибутом; `querySelector` без параметра-тип возвращает `Element`, у которого `.focus()` нет, поэтому селектор фокуса формы получил тип `HTMLElement`.
